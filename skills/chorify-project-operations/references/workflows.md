# Chorify 任务工作流

## 创建与分工

1. 读取项目成员、关联需求、版本和依赖任务。
2. 把目标拆成可独立验收的任务，填写交付物、验收标准、优先级和截止时间。
3. 按用户明确指定或描述中第一个被提及且最相关的人确定负责人；必须使用成员查询返回的 ID。
4. 显式验收人优先；否则关联需求提出者为验收人，未关联需求时由创建人验收。
5. 写入后重新读取，确认负责人、验收人、关联资源和初始状态。

## 推进与验收

1. 负责人完成工作并提供验证方式、遗留问题和所需支持。
2. 负责人将任务推进到 `PENDING_ACCEPTANCE`；没有验收人时先补充验收人。
3. 指定验收人按验收标准核对任务、依赖、汇报和交付物。
4. 通过时提交 `PASS`，任务闭环为 `DONE`；不通过时提交 `NEEDS_CHANGES`，并写明复现方式和修改要求。
5. 项目所有者、经理或团队管理员不能代替指定验收人作结论。
